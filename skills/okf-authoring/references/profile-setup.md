# Profile setup

This portable setup procedure accompanies the [complete field reference](profile-format.md). Copying a skill does not install an MCP server. Obtain a profile-capable `okf-mcp` executable through your normal installation process; verify that its `--help` advertises `--profile` and that its tool catalog exposes graph tools. No source checkout is required.

1. Choose the intended repository scan root. Place `.okf-profile.yaml` there. Use the practitioner's evidence ledger to adapt the complete example in the field reference to your actual types, headings and accepted obligations.
2. Configure your MCP host to launch the executable with arguments `--profile .okf-profile.yaml` and process working directory set to that scan root. Use your host's current configuration format; preserve other servers/settings. The explicit flag rejects unreadable/invalid profiles at startup rather than silently falling back. Add `--enable-hidden` only if relevant documents live under hidden directories; VCS internals remain skipped.
3. Reconnect/restart after editing the profile. One startup-selected profile applies across nested bundles; graph rebuilds do not reload it. Check stderr for `loaded profile`, confirm the actual executable and root, then call `get_index` to verify document discovery.
4. Query `graph_relationships` on one actual source with its forward relationship and on the target with the incoming inverse. Confirm endpoints and exact frontmatter types against the source link. Call `graph_integrity` with `checks: [profile_violations]`; inspect `profile_loaded` and findings. A loaded profile with neither relationships nor invariants can report false, so inspect the actual configuration rather than relying on that flag alone.
5. Check a missing required link and a wrong target type in an authorized disposable fixture. The first should trigger the accepted minimum; the second a type warning. Type warnings do not remove edges. Run document `validate_doc` separately: CLI `--validate` does not enforce graph integrity. Report unavailable or unexecuted checks as unproven.

Without explicit `--profile`, the server discovers `.okf-profile.yaml` at the scan root. Invalid discovered input warns and falls back to an untyped default; missing profiles also use the default. Zero findings in that state do not establish enforcement. See the field reference for exact schema defaults, selectors and a complete directional example.
